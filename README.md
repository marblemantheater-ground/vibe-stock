# vibe-stock

한국투자증권(KIS) OpenAPI 기반 미국주식 자동매매 프로그램 (Python 3.11+, asyncio).
Windows 와 macOS 에서 같은 저장소를 공유해 개발한다.

## 처음 설정 (기기마다 1회)

```bash
git clone https://github.com/marblemantheater-ground/vibe-stock.git
cd vibe-stock
```

1. `.env.example` 을 복사해 `.env` 를 만들고 앱키·시크릿·계좌번호 입력
   - Windows: `copy .env.example .env` / macOS: `cp .env.example .env`
   - `.env` 는 git 에 올라가지 않으므로 **기기마다 따로** 만들어야 한다.
2. 실행 (가상환경 생성·패키지 설치까지 자동)

| | Windows | macOS |
|---|---|---|
| 상시 실행 | `run.bat` | `./run.sh` |
| 거래일 하루만 실행 후 종료 (스케줄러용) | `run.bat --once` | `./run.sh --once` |
| N초 테스트 실행 (주문·정산 포함) | `run.bat --stream-test 60` | `./run.sh --stream-test 60` |
| 정산 보고서 보기 | `run.bat --report` (또는 `--report 2026-11-10`) | `./run.sh --report` |
| 연간 정산·예상 세금 | `run.bat --annual` (또는 `--annual 2026`) | `./run.sh --annual` |
| 백테스트용 분봉 수집 | `run.bat --collect-minute` | `./run.sh --collect-minute` |
| 백테스트 (최근 20거래일) | `run.bat --backtest` (또는 `--backtest 10`) | `./run.sh --backtest` |
| **긴급 정지** (미체결 취소 + 전부 매도 + 매수 중지) | `kill.bat` 더블클릭 또는 `run.bat --kill` | `./run.sh --kill` |
| 일시정지 (신규 매수만 중지, 매도는 계속) | `run.bat --pause` | `./run.sh --pause` |
| 매매 재개 (손실 한도·긴급 정지·일시정지 해제) | `run.bat --resume` | `./run.sh --resume` |
| 손실 차단 상태 보기 | `run.bat --risk-status` | `./run.sh --risk-status` |

## 대시보드 (브라우저 화면)

매매 프로그램(`run.bat` / `./run.sh`)이 실행되는 동안 **http://127.0.0.1:8765** 에서 볼 수 있다. 이 PC 에서만 접속된다.

- 로그인 비밀번호: `.env` 의 `DASHBOARD_PASSWORD` (비우면 실행할 때마다 임시 비밀번호를 콘솔 창에 표시)
- **매매 제어** 버튼: 일시정지 · 재개 · 긴급 정지 (긴급 정지는 확인 문구 `긴급정지` 입력 필요). 장 외 시간에 누르면 다음 세션 시작 때 적용
- **실시간** 탭: 총자산·오늘 손익·손실 한도 사용률, 보유 종목(익절·손절까지 거리), 오늘 주문, 최근 이벤트, 감시 종목(이동평균 추세) — 1초마다 갱신
- **정산** 탭: 일별 총자산·실현손익 그래프, 일별 요약, 날짜별 매매 상세
- **백테스트** 탭: 저장된 1분봉으로 실제 전략 코드를 돌려 본다. 기간·종목·바꿔 볼 값을 고르고 실행 →
  수익률(단순 보유와 비교)·최대 낙폭·승률·손익비·청산 사유·거래 내역. 실행 기록끼리 비교하고, 마음에 드는 값은
  **이 값을 설정에 적용** 으로 설정 탭에 반영 (실행만으로는 설정 파일이 바뀌지 않는다)
- **거래 옵션** 탭: 전략 값(봉 단위·이평·등락률·익절·손절·자금 배분·세션) 묶음을 여러 개 만들어 두고 **하나만 켠다**.
  켜면 새 매수부터 적용되고, **이미 보유한 종목은 산 때 옵션의 익절·손절·데드크로스 기준으로 판다**.
  옵션별 백테스트·실제 운용 성적(매매 내역에 옵션 이름 기록)을 카드에서 비교. 손실 한도·주문 규칙·수수료는 옵션과 무관한 공통 설정
  - 옵션마다 정할 수 있는 것: 매매할 세션(프리·정규·애프터 중 1~3개), **하루 목표 수익**(오늘 손익이 하루 시작 예수금의 N% 이상
    → 보유 전부 매도 후 그날 종료, 다음 거래일 자동 재개), **하루 최대 매수 횟수**(매도는 막지 않음), **최대 보유 종목 수**
    (닿으면 새 종목 매수 중지, 하나 팔리면 재개), 1회 매수 금액(자금 배분), **매도 후 재매수 대기(초)**
    (같은 종목을 판 뒤 이 시간 동안 다시 사지 않음. 같은 날 재매수는 `[order] max_buys_per_symbol` 도 2 이상이어야 함)
- **스캘핑** 탭: 스캘핑 템플릿(박스 돌파 · VWAP 눌림 반등 · 시가 범위 돌파)으로 거래 옵션 만들기 → 백테스트 → 켜기,
  왕복 수수료 손익분기 경고, 오늘의 왕복 매매(보유 시간·청산 사유·수수료 차감 손익, 스캘핑만/전체),
  보유 종목 청산 상태(추적 손절가·시간 청산까지·마감 정리 시각), 감시 종목 지표(VWAP·돌파 기준가·시가 범위 고가 대비,
  거래량 배수, 체결강도, 스프레드) — 2초마다 갱신
- **설정** 탭: 매수 조건·익절·손절·자금 배분·주문·손실 한도를 바꾸면 `config/strategy.toml` 에 기록(주석 유지)되고
  실행 중인 매매에 바로 적용된다. 봉 단위·이동평균 기간은 다음 거래일부터. 바뀐 내용은 이벤트·슬랙에 `[설정 변경]` 으로 남는다
  - 안전 스위치(`dry_run`, `allow_real_trading`, `cancel_open_orders_on_start`)는 화면에서 바꿀 수 없다 → 파일을 직접 수정
  - `strategy.toml` 을 직접 고쳐도 몇 초 안에 같은 방식으로 반영된다 (문법 오류면 알림만 보내고 기존 값 유지)
- 끄거나 포트를 바꾸려면 `config/strategy.toml` 의 `[dashboard]`

화면을 고칠 때만 Node.js 가 필요하다 (실행하는 PC 에는 필요 없음):

```
cd web/frontend
npm install
npm run dev     # 개발 서버 http://localhost:5173 (매매 프로그램이 실행 중이어야 데이터가 보임)
npm run build   # web/dist 갱신 → 커밋
```

## 정산 데이터 (`data/reports/{paper|real}/`)

| 파일 | 내용 |
|---|---|
| `trades/YYYY-MM-DD.csv` | 그날 주문 전체 (주문 1건 = 1행, 거부·취소 포함) |
| `daily/YYYY-MM-DD.json` | 그날 정산 보고서 (손익·수익률·보유 종목·매매내역) |
| `daily_summary.csv` | 하루 1행 누적 요약 — 엑셀로 바로 열림 |
| `annual/YYYY.json`, `annual/YYYY_sells.csv` | 연간 정산 결과와 매도 상세 (`--annual` 실행 시) |

- 날짜는 미국 현지 거래일 기준. 일별 실현손익은 수수료·세금 제외 추정치.

### 연간 정산 (대시보드 정산 탭 → 연간·세금, 또는 `--annual`)

해외주식 양도소득세 **추정**. 실제 신고는 증권사 양도세 계산 자료로 확인한다.

- 연도 구분은 **결제일**(체결일 다음 영업일, T+1) 기준 → 12월 마지막 거래일 매도는 다음 해
- 양도차익(원) = 매도금액 − 매도 수수료(원화: 매도 결제일 환율) − 취득가·매수 수수료(원화: 매수 결제일 환율)
- 같은 해 이익·손실 상계 → 기본공제 250만원 → 세율 22% (지방소득세 포함) → 다음 해 5월 확정신고
- 취득가: 선입선출(기본) 또는 이동평균 — `[tax] cost_method`
- 수수료: `[fees]` 매매 수수료(기본 0.25%), SEC 수수료·FINRA TAF(매도) — 실제 계약 수수료로 바꿔 쓴다 (설정 탭에서도 변경)
- 환율: 거래일마다 정산 보고서에 KIS 환율을 기록한다. 기록 없는 날은 가까운 날 환율로 추정하고 화면에 표시
- 프로그램 밖(HTS·기록 이전)에서 산 종목을 팔면 매도 시점 매입평균가로 취득가를 추정하고 표시
- 다른 증권사 계좌의 해외주식 손익, 배당, 환전 수수료는 포함하지 않는다
- `data/` 는 git 에 올라가지 않으므로 Windows/macOS 각각 따로 쌓인다.

## 백테스트

- 데이터: KIS 분봉 조회는 **최근 약 한 달(22거래일)** 만 준다. 처음 한 번 `--collect-minute` 으로 받고,
  이후에는 매매 프로그램이 거래일이 끝날 때마다 관심·선정·저장 중인 종목의 분봉을 이어 받아 기간이 늘어난다
  (`[backtest] collect_after_close`). 모의 서버는 초당 2건이라 처음 수집은 종목당 1분 30초쯤 걸린다
- 재현: 1분봉을 시가 → 저가/고가 → 종가 틱으로 바꿔 실제 전략 클래스에 넣는다. 봉 안에서 익절·손절 가격을 지나가면
  그 가격에서 체결한 것으로 본다. 하루 주문 한도·종목당 매수 횟수·최대 보유 종목·종목당 예산·수수료·손실 한도도 실제와 같게
- 체결은 신호 가격에서 `체결 미끄러짐`(기본 0.05%)만큼 불리하게 즉시 전량 체결된다고 가정한다 (미체결·호가 잔량은 재현 못 함)
- 거래 수가 적으면(30건 미만) 결과의 우연성이 크다 — 화면에 경고가 나온다

## 기능 켜고 끄기 (설정·거래 옵션·백테스트 탭의 스위치)

각 칸 이름 앞의 **켬/끔 스위치**로 기능을 끈다. 끈 기능의 값은 그대로 남아 있어 다시 켜면 예전 값으로 동작한다.
파일에는 섹션마다 `off = ["trailing", "take_profit"]` 처럼 꺼 둔 기능 이름이 기록된다 (예전 방식 '값 0 = 끔'도 그대로 통함).
거래 옵션마다 따로 저장되고, 보유 종목은 **산 때 옵션의 켬/끔 상태**로 판다.

| 섹션 | 끌 수 있는 기능 (off 이름) |
|---|---|
| `[ma_cross]` (거래 옵션) | 등락률 범위 `change_rate` · 신호 간격 `cooldown` · 매도 후 재매수 대기 `rebuy_wait` · 돌파 거래량 배수 `volume` · 추적 손절 `trailing` · 최대 보유 시간 `max_hold` · 마감 전 정리 `flatten` · 체결강도 `strength` · 스프레드 `spread` · 익절 `take_profit` · 손절 `stop_loss` · 데드크로스 매도 `dead_cross` · 주문가능금액 사용 비율 `capital_usage` · 하루 목표 수익 `daily_target` · 하루 최대 매수 횟수 `max_buys_per_day` · 최대 보유 종목 수 `max_positions` |
| `[order]` (공통) | 종목당 하루 매수 횟수 `buys_per_symbol` |
| `[risk]` (공통) | 하루 손실 한도 `daily_loss` · 최대 낙폭 한도 `max_drawdown` |

- **손절**은 추적 손절·최대 보유 시간·마감 전 정리 중 하나 이상이 켜져 있을 때만 끌 수 있다
- **주문가능금액 사용 비율**을 켜려면 최대 보유 종목 수도 켜야 한다 (예산을 나누는 수). 종목 수를 끄면 고정 금액만 쓴다
- 끌 수 없는 것: 세션·봉 단위·이평 기간·진입 방식(하나를 고름), 1회 고정 금액, 주문 동작 값, **하루 최대 주문**(마지막 안전판),
  수수료·세금, 안전 스위치

## 스캘핑 (거래 옵션의 진입 방식 · 청산 · 거르개)

| 항목 | 내용 | 백테스트 |
|---|---|---|
| 진입 방식 | 이평 교차(기존) / 박스 돌파(직전 N봉 고가) / VWAP 눌림 반등(상승 추세에서 VWAP 터치 후 양봉) / 시가 범위 돌파(정규장 첫 N분 고가) | ✅ |
| 돌파 거래량 배수 | 돌파 봉 거래량이 평균의 N배 이상일 때만 | ✅ |
| 추적 손절 | 고점이 +A% 오르면 켜지고, 고점 대비 −B% 밀리면 매도 | ✅ |
| 최대 보유 시간 | 산 뒤 N분이 지나면 매도 | ✅ |
| 마감 전 정리 | 마지막 선택 세션 종료 N분 전 전부 매도 + 매수 중지 | ✅ |
| 체결강도 하한 · 스프레드 상한 | 실시간 틱 값으로 매수 거르기 | ❌ (분봉에 없음) |

- 스캘핑 방식으로 산 종목의 청산은 `신호 간격`에 막히지 않는다 (이평 교차 종목은 기존과 같음)
- 같은 종목을 하루에 여러 번 사려면 `[order] max_buys_per_symbol` 을 0 또는 2 이상으로
- **수수료에 매우 민감하다.** 왕복 수수료(기본 0.25% × 2 ≈ 0.5%)보다 익절 폭이 충분히 커야 한다.
  2026-10-16~11-16 실제 분봉(6종목) 백테스트에서는 템플릿 3종 모두 수수료 전에도 손실이었다 → 그대로 쓰지 말고 조정·검증할 것

## 손실 차단 (`config/strategy.toml` [risk])

| 장치 | 발동 조건 (기본값) | 동작 | 해제 |
|---|---|---|---|
| 하루 손실 한도 | 오늘 시작 총자산 대비 -5% 가 10초 이상 | 신규 매수 중지 (익절·손절 매도는 계속) | 다음 거래일 자동 |
| 최대 낙폭 한도 | 고점(일별 마감 총자산 최고치) 대비 -15% | 신규 매수 중지 | `--resume` |
| 긴급 정지 | `kill.bat` / `--kill` / 대시보드 버튼 | 미체결 전부 취소 + 보유 전부 매도 + 매수 중지 | `--resume` / 재개 버튼 |
| 일시정지 | `--pause` / 대시보드 버튼 | 신규 매수 중지 (매도는 계속) | `--resume` / 재개 버튼 |

- 총자산 = 주문가능 USD + 보유 평가금액(실시간 체결가). `*_action = "liquidate"` 로 바꾸면 한도 발동 시에도 전부 매도.
- 매매 프로그램이 실행 중이면 `--kill`/`--resume` 은 몇 초 안에 반영된다. 꺼져 있으면 장중엔 그 자리에서 청산, 휴장이면 다음 실행 때 청산.
- 상태는 `data/risk/{paper|real}.json` 에 저장되어 재시작해도 유지된다.
- 입출금이 있으면 총자산이 달라져 한도가 잘못 발동할 수 있다 → 입출금 후 `--resume` 으로 기준점을 다시 잡는다.

## Windows ↔ macOS 공유 규칙

- **줄바꿈**: `.gitattributes` 로 모든 텍스트 파일을 LF 로 고정 (`*.bat` 만 CRLF).
  각 기기의 `core.autocrlf` 설정과 무관하게 동일하게 저장된다.
- **경로**: 코드에서는 항상 `pathlib.Path` 와 `/` 연산자를 사용한다.
  `"data\token.json"` 같은 문자열 경로나 `C:\...` 같은 절대경로는 쓰지 않는다.
- **인코딩**: 파일 읽기/쓰기에는 항상 `encoding="utf-8"` 을 명시한다
  (Windows 기본값 cp949 와 macOS 기본값 utf-8 이 다르기 때문).
- **기기별 파일은 커밋하지 않음**: `.env`, `data/`(토큰 캐시), `logs/`, `.venv/`
- **두 기기에서 동시 실행 금지**: KIS 는 앱키당 웹소켓 세션을 1개만 허용한다.
  한쪽에서 매매 프로그램이 돌고 있으면 다른 쪽은 종료한 상태로 개발한다.
